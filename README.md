# 架空地图生成器（Fantasy Map Generator）

纯前端、零构建的程序化架空世界地图生成器。打开页面即自动生成一张
1600×800（2:1 经纬网格，默认罗宾逊投影）的世界地图，支持 5 种视图、
3D 球体、地形编辑、高清导出与配置存档。

## 特性

- **无缝球面噪声**：地形在 3D 球面上采样，左右无接缝、两极无放射状拉伸。
- **板块构造**：球面 Voronoi 划分板块，陆陆碰撞造山、海沟、火山岛弧与岛链。
- **精确海陆比**：全局高度排序后取分位值作为海平面，海洋占比可精确控制。
- **气候模拟**：行星风带 + 边界感知洋流（Gyres）+ 地形雨/雨影 + 大陆性干燥。
- **真实水文系统**（见下文）：填洼 → 流向 → 汇流累积 → 分级河网与湖泊。
- **生态群系**：Whittaker 温湿矩阵，含极地冰盖、沙滩、高山冻原等特殊地貌。
- **地图编辑**：画笔抬升/压低地形、抚平、套索重绘、撤销/重做。
- **3D 球体**：three.js 球体贴图 + 顶点位移地形 + 体积云 + 大气辉光。
- **多视图**：地形混合 / 纯地形 / 纯等高线 / 气候热力图 / 自然群系。
- **导出**：带标准图例的高清 PNG；配置可导出为 JSON 再导入。

## 运行方式

无需构建、无需依赖安装，直接用浏览器打开 `index.html` 即可。

如需本地服务（推荐，部分浏览器对 file:// 有限制）：

```bash
python -m http.server 8080
# 然后访问 http://localhost:8080
```

> 2D 与 3D 全部离线可用：three.js、OrbitControls、simplex-noise 均已本地化到 `js/vendor/`。

### 打包成单文件

```bash
node build.js          # 产出 dist/index.html
```

零依赖（只用 Node 内置模块）。产物约 990 KB，把 CSS、15 个脚本、
以及地形 Worker 的源码全部内联进一个 HTML：

- Worker 走 `Blob URL` 创建，源码注入 `window.__FM_WORKER_SRC__`
  （跨域与 `file://` 下无法 `new Worker('js/terrain-worker.js')`，这是绕法）；
- 构建时用 `vm.Script` 预解析 Worker 源码，语法错在构建阶段就报，不留到运行时；
- 内联时把 `</script` 打断成 `<\/script`，避免脚本文本提前闭合标签；
- 构建后自带校验：无外链残留、脚本按序可执行、模块全部挂载。

`node tools/verify-build.js` 会对产物做 10 项检查，其中包含
「内联 Worker 与源码版逐位一致（diff 0）」。

## 生成管线

1. **A 地形**：球面 3D 噪声 + 域扭曲 + 板块 Voronoi 距离，接缝处造山/海沟/岛弧。
   按行带切给多个 Web Worker 并行计算（见「性能」一节）。
2. **B 海平面**：对全部高度排序，按「海洋占比」取分位值。
3. **C 气候**：纬度温度、海拔递减、行星风带、洋流环流、温湿传输与雨影。
4. **D 水文**（核心）：见下节。
5. **E 群系**：温度 × 湿度 → Whittaker 矩阵。

每个阶段都会通过 `onProgress` 汇报进度并让出主线程，界面不会假死。

## 水文系统（hydrology.js）

旧实现「从随机源点沿严格下坡走 80 格才算河」在程序化地形上几乎必定踩进
局部洼地，实测出图 0 条河。新实现改用真实水文学流程：

1. **填洼（Priority-Flood + ε）**：从海岸线与南北边界向内推进，把每个洼地
   填到溢出高度并保留极小梯度，保证每块陆地都有严格下降的排水路径。
2. **D8 流向**：每格指向 8 邻域中最低的邻居，海洋/地图边缘视为出口。
3. **汇流累积**：按填平后高度从高到低把水量推给下游，得到每格汇水面积。
4. **河网提取**：汇水面积超过阈值（默认约为地图格数的 0.095%）的格子组成
   河道；从每条支流源头沿下游回溯成折线，按汇水面积分 4 级宽度渲染。
5. **湖泊**：填平区域中成片的部分即湖泊（面积过小的洼地按湿地忽略），
   湖面按像素掩码渲染并加深湖岸线。

渲染层再对河段做**曲流扰动**（沿路径法线叠加低频噪声）与贝塞尔平滑，
让 D8 的 45° 折线看起来像自然河曲；极地冰盖范围内不绘制水系。

实测（1600×800，桌面浏览器）：水文计算约 0.6 s，生成 55~90 条河段、
35~46 个湖泊。

## 地图编辑

编辑器只做一件事：**圈一块地，让它变成大陆，或者变成海洋**。

1. 勾选「开启地图编辑」。
2. 在地图上按住拖动画一个圈（红色闭合选区）。
3. 点「🏔️ 隆起成大陆」或「🌊 沉陷成海洋」。
4. 成形是同步的（大选区约 0.3 s），海深与河流随后自动重算。
5. `Ctrl+Z` / `Ctrl+Shift+Z` 撤销重做（历史上限 15 步）。

两个滑块：

| 滑块 | 作用 |
| --- | --- |
| **隆起幅度** | 最高处占「陆地可用高度」的比例。0.82 大致摸到雪线，0.5 是一片低缓大陆 |
| **地貌尺度** | 乘到选区内切半径上。>1 得到更整块的大陆、更少更大的山带；<1 得到碎岛群 |

### 为什么删掉了笔刷

上一版有五个笔刷工具（造山脊 / 挖谷地 / 冲蚀 / 抚平 + 套索）。它们换来了一整套
单笔成形质量的改进 —— 等弧长节点、各向异性轴线、不对称横剖面、双层剖面、
域扭曲 ridged 噪声、热力 + 水力侵蚀 —— 但模型本身有个天花板：

> **笔刷只能在已有大陆上刻出局部起伏，造不出一块新大陆。**
> 海岸线还是原来那条。

所以无论参数怎么调，观感都停在「在图上涂抹」。要实现"选中的部分自动隆起成
一片有海岸线、有山带、有河流的大陆"，必须换一层更底层的表达：**从选区的软掩膜
直接生成高度场**，让海岸线由噪声决定，而不是由多边形的边决定。

笔刷的算子（`StrokeWalker` / `stampSegment` / `synthesize` / `smoothRegion`）
仍保留在 `terrain-ops.js` 里并有 12 项测试守着，但**编辑器不再接线**。

### 两个函数就是全部

```
套索多边形
  └─ buildSelectionMask   多边形 → 精确 EDT → 软掩膜 mask + 内陆度 shelf + 尺度 sc
       └─ shapeRegion     两遍：synthesizeRegion（板块构造）→ 分位映射到 FM.HYPSO
            ├─ drainFill 内陆封闭洼地抬平（离海 ≥9 格才动，海岸带原样）
            └─ erode     热力 + 水力侵蚀（只写回选区内）
```

#### ① `buildSelectionMask`：把海岸线打碎

1. 扫描线填充多边形 → 内距图；
2. **精确欧氏距离变换**（Felzenszwalb & Huttenlocher，`edt1d` + `edt2d`）求内距 `dIn`；
   再对反转图求一次得到外侧距离 `dOut`，拼成符号距离 `sd`（内正外负）。
   *不要退回 8 邻域倒角*：对角误差约 8%，而且 8 重对称会在岸线留下放射状条纹。
   距离变换的哨兵值用 `EDT_INF = 1e18`，不能用 `Infinity` —— 抛物求交会算出
   `NaN`，而 `NaN <= z[k]` 恒 false，会静默写坏单调栈。
3. `shelf`（内陆度）只用**大尺度**位移：`shelf = smoothstep((sd + bias + wLow·cap) / (0.30·sc))`；
   `bias = 0.10·sc`，所以**岸线处 shelf ≈ 0.26 而不是 0**（后面 taper 要用到这一点）。
4. `mask = smoothstep((sd + bias + wm·cap) / band)`，`wm = clamp(1.35·w)`；
   **过零线就是新海岸线**。

四层噪声的波长挂在**图宽**上（与 `terrain.js` 同源），权重如下：

| 层 | 波长 | 权重 | 负责 |
| --- | --- | --- | --- |
| f1 | W/3 ≈ 333 格 | 1.00 | 半岛与大海湾（也用于 `shelf`） |
| f2 | W/7 ≈ 143 格 | 0.52 | 大岬角 |
| f3 | W/20 ≈ 50 格 | 0.45 | 小海湾 / 潟湖 |
| f4 | 9 格 | 0.22 | 岸边碎屑 |

**为什么 `wm` 要 ×1.35**：四层 fbm 实测合成 `w` 只有 0.15~0.35（层间互相抵消），
乘 `cap` 只有 6~14 格，岸线只是"缓弯"——掩膜本身破碎度只有 1.28（几乎是个圆）。
放大 1.35 倍后位移到 8~19 格，f3/f4 才真正把岸线搓出岬角与潟湖。
只放大 `mask`；`shelf` 仍用未放大的 `wLow`，内陆高度分布不受影响。

#### ② `shapeRegion`：两遍 + 排水保证

高度不是 `掩膜 × 幅度`（那只会得到一块橡皮泥台地）。现在的顺序是：

1. **第一遍只算"起伏量"**，存进 `amt` 缓冲。
   起伏量 = `elev × k × synthesizeRegion(...)`。
   - `synthesizeRegion` 在选区里跑一次**小规模板块构造**：4~7 个陆壳板块核、
     平面 Voronoi、接缝碰撞段掩码、起伏包络、主山系 `beltBoost`、山脊 ridged。
     这比"画一条山链"更像大陆：山是碰撞的副产品，走向、宽窄、断续、多峰
     都由碰撞样式决定。
   - `elev = 0.30 + 0.70 · smoothstep((sh − 0.26) / 0.61)`。
     **不能写 `sh / 0.30`**：岸线 `sh` 已经是 0.26，那样等于岸线就有 0.87，
     整块大陆连海岸都是满高度，没有海岸平原，岸线也被抹成一条光滑等值线。
2. **第二遍做分位映射**：`relAt = buildRelMapper(amt, ...)`，把起伏量的分位
   映射到 `FM.HYPSO` 的测高曲线（陆地 p50≈0.04 / p90≈0.20，与生成器同源）。
   映射是单调的，所以海岸线位置、山谷走向、山脊逐格保留，改变的只是等高线间距。
   映射**之后**再加两层海岸噪声（22 格大海湾 + 9 格碎岬角）和一层 7 格微纹理；
   加在映射之前会被分位归一化抵消。
3. **排水保证 `drainFill`**：塑形区里只要有一处"四周都比它高、自己没出口"的
   锅底，水文阶段就会灌成湖（小选区实测 9.4% 水面）。做法是从**外海**做一遍
   BFS，只对「离海 ≥9 格」的内陆格子做 priority-flood（Barnes）：种子是海
   岸带 / 选区外的边界格，锅底抬到最低溢出口；**离海 9 格以内一律不动**，
   潟湖、沙嘴、岩礁保留。海盆模式跳过。
4. 写回时按 `next = before + (target − before) · m` 混合，`m=0` 的格子绝不改；
   气温按 `FM.LAPSE` 同一条直减率修正（不能在这里再写一个 0.45）。

### 这一轮返工踩到的坑（按发现顺序）

| 症状 | 原因 | 修法 |
| --- | --- | --- |
| 新大陆像**贴上去的褐色瘤子** | 塑形高度与生成器不同源：新大陆 rel 中位 0.45，全世界 0.041（高 11 倍） | 抽出 `js/hypsometry.js`（`FM.HYPSO`），两端共用同一条测高曲线；`buildRelMapper` 做分位映射 |
| 岸线像**用铅笔描的多边形** | 掩膜四层 fbm 互相抵消，`w` 只有 0.15~0.35，位移 6~14 格 | 掩膜位移 ×1.35；A3/A4 提到 0.45/0.22 |
| **海岸平原消失**，近岸和内陆一样高 | `shelf` 岸线处已是 0.26，却拿 `sh/0.30` 归一 → 岸线 taper 0.87 | 改成 `(sh − 0.26) / 0.61` |
| 小选区 **9.4% 是水面**（内陆海） | 板块 `hOff` + 分位映射凑出封闭洼地，水文逐个灌成湖 | `drainFill`：只抬离海 ≥9 格的内陆洼地 |
| 第一版排水把**海岸潟湖也填平** | 全图所有洼地一律抬平 | 先 BFS 分外海连通水，海岸带 9 格内不动 |
| 合成 **400 ms** 顶到预算 | bbox 比选区大 3 倍，`synthesizeRegion` 把掩膜外也算了 | 掩膜 `<=0.002` 直接跳过（28 万格 → 9 万格） |

> **几个判据本身被返工过，记在这里免得再踩：**
> - 用「landE 与距海距离的 Pearson r」判"有没有海岸平原"是错的：整块大陆的
>   中央可能正好落在低频盆地里，那里离海最远、高度却最低，把相关系数拉平到
>   −0.03 ~ 0.26。改成**近岸带 vs 内陆带的均值比**才对。
> - 用「p99 / 平均坡度下降」判"侵蚀有没有起作用"也是错的：水力侵蚀会切出
>   河谷，河谷两壁本来就是陡岸，坡度上升不是 bug。改成 **Δe 与局部高差的
>   负相关**（削峰填谷）才对。
> - 「历史只记变化格」必须按 `Math.fround` 比较。快照是 `Float32Array`、
>   数据是 float64，按 float64 比会记进一堆"前后完全相同"的空记录。


## 渲染要点（避免"横线"与"割裂"）

这几类问题在开发中都真实出现过，修复方式记录在此，便于后续改动不踩坑：

- **贯穿全图的横线**：地图在 X 方向环绕，河流跨经线时 x 会从 0 跳到宽度。
  渲染时必须先**解缠（unwrap）**再画，并在绘制时按 `k*W` 环绕复制副本，
  否则会拉出一条横线。见 `renderer.js` 的 `emitWrappedPath()`。
- **极地冰盖的横线**：冰盖边界不能只按纬度切分，也不能用带强水平分量的
  低频噪声，否则会出现一条笔直横线或横向条纹。现在由「纬度趋势 × 各向同性
  高频噪声 + 海拔」共同决定，极点附近 2% 收敛为纯冰色。
- **板块割裂**：海底在板块接缝处（海沟、造山带）有剧烈突变，直接按高度
  着色会画出锐利的深蓝裂缝。现在海洋使用**模糊后的海深场**
  （`renderer.updateOceanDepth()`），板块接缝在视觉上被抹平。
- **尖锐山峰**：地形逐格计算会留下 1 格宽的尖脊，渲染成刺眼的白/黑点。
  生成阶段用 **3×3 中值滤波**削掉离群尖刺（不是高斯平滑，避免磨平细节），
  渲染阶段把等高线色带改为连续插值、山体阴影改为中心差分并压缩对比度。
- **板块边缘的台阶**：板块高度偏移曾取自离散的「大陆 +0.1 / 海洋 -0.1」，
  在板块三点交汇处最近/次近板块互换，配对从 (A,B) 突变成 (B,C)，
  会产生 0.10 的高度阶跃。现在每块板块分配**连续**的偏移量，
  并用**反距离加权**混合全部板块，空间上处处连续，台阶消失
  （实测跨板块相邻格最大高差从 0.107 降到 0.042，台阶数为 0）。

## 投影系统（projection.js）

地图数据始终是**等距经纬网格**（1600×800 对应经度 360°、纬度 180°），
投影只发生在渲染阶段：遍历目标像素 → 反算经纬度 → 双线性采样数据网格。
因此生成、编辑、水系、存档的坐标系统完全不受投影影响。

| 投影 | 特点 |
| --- | --- |
| 等距圆柱 | 传统 2:1 地图，经纬线为直线，极点为整行 |
| 罗宾逊（默认） | 伪圆柱，极地收拢成一点，高纬压缩自然 |
| 摩尔威德 | 等面积椭圆，极点是椭圆两端的一个点 |

**为什么要做投影**：等距圆柱把极点那一「点」铺满整整一行，
极地永远是一条横贯全图的横条，靠调噪声无法根治。
换成罗宾逊/摩尔威德后，极点收缩为一点，横条问题从几何上消失。

> 注：罗宾逊的极点其实是一段约为赤道宽度 53% 的**线段**（不是点），
> 摩尔威德才是收缩成一个点。

### 矢量叠加层必须跟着投影走（曾经的「河流跑到图外」）

地形是「逐画布像素反算经纬度」画出来的，所以它**自动**适配任何投影。
但河流、经纬网、季风、洋流这些是**矢量叠加**，原先一律按数据坐标
（等距圆柱像素）直接连线 —— 在罗宾逊/摩尔威德下就画到了椭圆外面，
表现为「河流跑出地图」。

现在统一由一对换算函数处理：

| 函数 | 方向 | 用途 |
| --- | --- | --- |
| `projectPixel(px, py)` | 数据坐标 → 画布坐标 | 河流/经纬网/洋流/季风绘制、编辑器叠加层 |
| `unprojectPixel(x, y)` | 画布坐标 → 数据坐标 | 编辑器指针输入、局部重绘采样 |

各投影的 `forward()` 对经度都是线性的，所以传超出一圈的坐标
（跨经线的解缠副本）也能连续外推。

**跨经线的副本还要额外裁剪。** 河流跨 ±180° 时解缠坐标会越过地图边界：
等距圆柱下只是画到画布外、被自然裁掉，但罗宾逊下 ±180° 正是椭圆轮廓，
越界后投影结果会**落进椭圆四角的空白区**。因此绘制河网、经纬网、
洋流、季风前都会调用 `clipToProjection()`，用投影轮廓做一次 canvas 裁剪。

实测（逐层差分，统计落在投影外的像素）：

| 投影 | 河流越界像素 | 经纬网越界像素 |
| --- | --- | --- |
| 罗宾逊 | 0 / 3487 | 0 / 10912 |
| 摩尔威德 | 0 / 5326 | 0 / 10912 |
| 等距圆柱 | 0 / 5326 | 0 / 10912 |

编辑器同理：指针坐标在入口就反算成数据坐标（`unprojectPixel`），
叠加层绘制时再投影回去（`projectPixel`），否则在罗宾逊图上
点击会编辑到错误的格子、笔刷光标也会与实际影响范围不符。

## 地貌细节的取舍（避免「光滑鼓包」与「陨石坑」）

这条路踩过两次坑，记录如下：

1. **过度平滑**：早期用 3 遍 3×3 高斯平滑去除单格尖刺，结果把整片地形
   的高频细节一起磨平（陆地平均二阶差分仅 0.00049），山坡变成
   「边缘平滑、形状突兀」的光滑鼓包。
2. **过度随机**：改为给全图均匀叠加各向同性噪声后，又出现满地图
   随机小凸起与小坑的「陨石坑感」（局部极值 10.3 个/千格）。

现在的做法（`map-generator.js`）：

- **削峰**用 3×3 **中值滤波**（只替换离群点，不模糊正常地形），
  再按比例把细节层加回；
- **细节**用 **ridged noise**（`1-|n|`）生成成条成网的山脊线，
  而不是孤立圆包；
- **按海拔调制**：细节强度乘上高度掩膜，平原保持平整、山区才有纹理。
  粗糙度因此与海拔正相关（平原 0.0017 → 山地 0.0029），
  局部极值降到 4.2 个/千格，进入自然区间。

## 海拔分层与雪山

七档等高线色带：平原 / 丘陵 / 高地 / 浅山 / 中山 / 高山 / 雪线。

**这里踩过四个坑**，记录以免回退：

1. **色带空转**：早期地形被 `e**1.05` 和顶部 ×0.35 压缩，陆地相对高度
   最高只有 0.69，而雪线阈值是 0.90 —— 后面三档（中山/高山/雪线）
   永远是 0%，地图上不可能出现雪山。
2. **地球仪涂装**：改用「分位重标定」把高度按排名**均匀**铺开后走向另一极端 ——
   每块大陆都被机械分配到全部七档，色带变成同心环，雪山变成一块
   实心白色平台（边界高度落差中位数仅 0.016），整张图像地球仪涂装。
3. **随机缺雪山**：改成按「本图最高点」归一化后，最高点往往只是偶然的
   个别尖峰，多数图仍然没有雪线（四次里两次失败）。
4. **整块大陆都是高原**（第四次，也是这一轮才发现的）：修好 1~3 之后
   地形本身能出雪山了，但**高度的分布形状从来没人管过**。分形地形的原始
   高度场几乎是均匀分布，而真实陆地极度左偏。实测这块大陆的
   相对高度中位数 `rel p50 = 0.264`（≈2300 m）、`p90 = 0.643`（≈5700 m），
   对照地球应当分别是 0.04 和 0.23 —— **整体高了 5~6 倍**。

   后果全落在气候上，而且每一条都被当成「气候 bug」查了很久：
   - 雪线横扫：中位数就有 0.26，随便一块台地都越过雪线，
     实测 `climate-verify` 那张图 **22.6% 的陆地是雪地**；
   - 裸岩/高山冻原成片，大陆看起来是一片碎石高原，没有平原；
   - 草原几乎消失（高寒群系吃掉 35.5%，草原只剩 12.6%）；
   - `t -= rel·LAPSE` 把整块大陆压得比同纬度海洋冷，温带森林被压成针叶林。

**现在的做法**（`map-generator.js`）：

- 去掉所有粗暴压缩，只保留软限幅；
- **按真实测高曲线重分布**（`EARTH` 表）：把陆地按高度分位映射到地球的
  测高曲线（33% < 200 m、66% < 500 m、82% < 1000 m、93% < 2000 m）。
  实测结果与地球**逐分位对齐**：rel<0.023 占 33.0%、<0.057 占 66.0%、
  <0.113 占 82.0%、<0.226 占 93.0%。雪地随之从 22.6% 回到 1.6%；
- **这不是重走坑 2**：坑 2 是把高度**均匀**铺满七档（等于假设一半陆地是高山），
  现在是朝**强烈左偏**的真实曲线压缩。两者都用「分位」，但目标分布相反，
  而且映射是单调的 —— 等高线走向、山脊、谷地与原来逐格一致，
  改变的只是相邻等高线之间的间距（平原变宽、陡坡变陡）；
- 引入**大山脉系统**：在板块碰撞段之上再叠加一组大尺度山系
  （`beltMask`），让高峰成串、成带，而不是零散孤立；
- 保证「至少 2~3 块相邻的大陆板块」，确保陆陆碰撞必然发生 ——
  否则随机结果里可能全是海洋板块，根本无从造山。

**配套必须同时改的两处**（改一处不改另一处就会翻车）：

| 依赖 `rel` 标尺的地方 | 旧值（均匀分布地形） | 新值（测高曲线地形） |
| --- | --- | --- |
| `climate.js` 雪线 | `0.42 + 0.50·tSea` | 按真实雪线标定的分段表 |
| `renderer.js` 山体光照增益 `S` | `34` | `110` |

- 雪线：`rel` 的物理含义从「均匀分布的分位」变成「相对 8848 m 的高度」，
  阈值必须按米数重新标定（详见气候章节）；
- 光照：`S` 是「一格高差 → 法线倾斜」的放大倍数，必须与高度场的实际量级
  配套。平原区的 rel 从「每单位高度 2.1 个分位」变成 14.3 个分位，
  也就是同样一块平原高差缩小约 7 倍；`S` 仍取 34 时整片大陆的 `shade`
  贴着 1.0，光照完全消失，地图看起来像一张平涂色块。

实测：每张图稳定产生雪顶（雪地 1~5% 陆地），
并且**温带不再成片变苔原**（35~55° 高寒群系 0.7~18.6%，见判据）。


## 气候系统（climate.js）

旧实现把气候内联在 `map-generator.js` 里：风只是按纬度取 ±1 的水平方向，
洋流只给海温加减 0.15，没有季风，也不参与降水与植被循环。
现在独立成 `climate.js`，分五个阶段：

### 1. 行星风带（三圈环流）

赤道低压带 / 副热带高压带 / 西风带 / 极地东风带，用**高斯钟形叠加**实现。

> **踩过的坑**：早期用 `smoothstep(a,b) * (1 - smoothstep(c,d))` 分段拼接，
> 结果在 0°、30°、60° 处两组 smoothstep 同时为 0/1，**风速精确等于 0**。
> 水汽无法通过那些纬度，气候被切成死板的纬度条带（群系图呈水平带状）。
> 改为钟形叠加后风场处处连续，实测降水与纬度的相关系数从 -0.19 降到 0.003。

### 2. 季风系统

季风的物理本质是**海陆热力差异**：陆地比热小，夏季升温快形成低压，
风从海洋吹向陆地；冬季相反。实现上：

- 逐纬度统计陆地占比，得到「海陆热力差」；
- 每个格点找最近陆地方向，得到「向陆」矢量；
- 夏季 / 冬季两种相位分别计算，相加即得季风环流；
- 输出 `monsoon` 强度场，参与后续降水计算（雨季/旱季）。

季风是低纬现象，实测低纬（<30°）强度 0.14~0.20，高纬 0.03~0.08，符合物理规律。

### 3. 洋流系统

分两层，职责分开：**流场只用于绘制**，**温度/水汽效应另算一个场**。

**流场**（`oceanCurrents()`，写回 `cell.current`，供渲染层画流向箭头）：

1. 风生环流：风应力驱动表层流，北半球右偏 45°、南半球左偏（Ekman 近似）；
2. 西边界流：每行最左一段海洋上加经向流，低纬为暖流、中纬为寒流；
3. 海岸约束 + 3 次拉普拉斯平滑。

**海温异常**（`coastalSst()`，返回值 `warm ∈ [−1,1]`）：

> 一个海格若**左侧**陆地更近 → 它在海盆西缘（贴大陆东岸）→ 暖流；
> 若**右侧**陆地更近 → 海盆东缘（贴大陆西岸）→ 寒流。
> 离岸 `exp(−d/14)` 衰减，纬度窗 `5°~58°`。

为什么要拆成两个场：流场那套（风生环流 + 拉普拉斯平滑）**在经向上是完全均匀的** ——
行星风只依赖纬度，西边界流又只对每行最左一段海洋生效，再被平滑抹平。
实测东西岸海格的平均流速一模一样 `(u,v)=(−0.25,0.00)`，
用它算出的 `tempEffect` 对沿海陆地的温差只有 0.001~0.009，等于没有。
而真实地球的副热带分界不是纬度、是「这块陆地贴的是暖流还是寒流」：
西岸贴东边界寒流（上涌、层结稳定）→ 沿海沙漠；东岸贴西边界暖流 → 湿润亚热带。

`coastalSst` 只用海盆几何，不依赖任何风场，因此稳定、不受平滑影响。
它同时驱动两个量：

- **温度**：`t += sstField · 0.13`（`sstField` 对陆格取最近海岸海格的值，
  再按 `exp(−d/14)` 衰减；BFS 顺带记录 `seaSrc`）；
- **水汽**：海面 `floor = (0.28 + 0.72·rowBase) · exp(0.85·warm)`。

### 4. 水汽输运与降水

沿风向多遍推进：海洋蒸发 → 随风进入陆地 → 遇山抬升成雨 → 背风坡雨影 → 内陆干燥。

> **踩过的坑**：① 迭代 40 遍会让整片大陆的水汽趋同，降水经向变幅只有 0.07；
> ② 写成 `max(自身, 上游)` 会让水汽只增不减；③ 遍数太少（6 遍 × 2.2 格 ≈ 13 格）
> 则水汽根本进不了大陆内部，沿海被描出一圈等宽绿边。
>
> 现在：**22 遍 × 8 格 ≈ 176 格**的输送距离、`上游×0.90 + 本地×0.10`、
> 每遍 3×3 扩散 30%、逐遍净衰减 0.990。水汽能横穿半块大陆，
> 干湿由「沿途被山拦下」与大陆度决定，而不是一个武断的指数衰减。

> **但光靠平流在副热带完全行不通**：30° 恰好是副热带高压带（马纬度），
> 信风分量 `−0.85·e^−(15/13)² = −0.22` 与西风分量 `+0.95·e^−(15/14)² = +0.30`
> 几乎抵消，实测 `u = 0.077`。没有风就没有平流，22 遍推进 + 30% 扩散的
> 半径只有约 2.5 格 —— 海面水汽再按海温调，也只描出一条 2~3 格宽的绿边。
>
> 所以补了一项**海岸带的海上空气侵入**：让近岸陆地空气向「该处海面的
> 平衡水汽值」靠拢（`m = m·(1−0.45) + supply·0.45`）。暖流岸 → 海岸湿润；
> 寒流岸 → 海岸干燥。衰减由 `sstField` 自身承担，湿润带只有 40~60 格宽。

> **地形雨不能写阈值分支**：`if (rise > 0.010) {...} else {...}` 在阈值点上的
> 降雨量从 `m·0.012` 跳到 `m·0.09`（7 倍），降水图上一眼就能看到硬边的深蓝斑。
> 写成 `orographic = 0.012 + max(0, rise)·9`（坡度为零时正好退化成对流雨）。

### 5. 生态群系

用「温度 × 降水」的 Whittaker 图，并叠加海拔垂直分带（雪地 / 高山冻原 / 裸岩）。

#### 为什么原先「全是横向色带」

群系只由温度与降水决定，而这两者在旧实现里**几乎只是纬度的函数**，
等值线是一组水平直线，于是群系被画成一条条横贯大陆的色带。

真实地球在同一纬度上有撒哈拉、中国季风区、北美温带林，差别来自两件事：

1. **大陆度**：越深入内陆越干（多源 BFS 求到海岸距离，指数衰减湿度）；
2. **大陆尺度温度扰动**：冷涡/暖脊让等温线蜿蜒，不再笔直。

补齐这两项后，等值线随大陆轮廓弯曲，群系才成「块」而不是「带」。

#### 阈值必须按纬度反解

归一化温度是距赤道的函数：t = 1 - 0.92 × (|lat|/90)^1.15，
代入得 t(26°)=0.79、t(34°)=0.70、t(55°)=0.47、t(66°)=0.36、t(80°)=0.20。
旧阈值把 t<0.72 当作热带上限 —— 而 0.70 对应 34°，热带因此一路推到中纬、
温带被挤没（实测落叶阔叶林仅 1.2%、热带类合计 41.7%）。
现在把分界钉在真实纬度上：热带 ≲26°、亚热带 26~34°、温带 34~55°、
亚寒带 55~66°、苔原 66~80°、冰盖 80°+。

**冰盖要严格**：旧实现「降水 > 0.30 即冰盖」，而降水中位数就有 0.37，
等于把整个极区的苔原都判成冰盖（实测占陆地 18.6%）。
冰盖现在只在「极冷」或「极冷且降雪充沛」时出现。

**苔原 ≠ 高山冻原**：中纬高山因气温直减率也会很冷，但不能算极地苔原
（否则苔原南北横跨两半球、纬度标准差 44°）。按相对高度区分后，
苔原回归 66~80° 的纬向带（实测均值 69°、标准差 6.7）。

#### 河流与湖泊参与生态

生成管线是「气候 → 水文」：气候算群系时河流还不存在，算完也没人回头修正 ——
结果河流只是一条蓝线，撒哈拉里的尼罗河两岸和周围沙漠一模一样。

现在水文算完后追加一步 applyWaterInfluence()：以河流格/湖泊格为源做多源 BFS，
按距离衰减地抬升湿度、轻微调节温度，再重新分类群系。
影响半径 16 格（约 3.5° / 400km），强度系数 0.40。

> 半径与强度是从 22 格 / 0.58 收回来的：那个设置会把**一半以上的陆地**
> 推到「河边湿地」的湿度（`m = mBase + prox·0.58·(1−mBase)` 迅速饱和），
> 降水中位数被整体抬高 0.11、荒漠几乎消失，整块大陆变成同一片绿。
> 河流该造出的是**绿洲带**，不是把整个大陆泡湿。

> 编辑地形会触发重建水系，该步骤会被反复调用。因此气候阶段会保存
> mBase/tempBase 基准值，修正始终从基准值重算 —— 否则湿度逐次累加，
> 河边最终会变成沼泽（实测连续重建 3 次，均值稳定在 0.4244）。

实测分布随随机世界不同（每张地图的极地陆地面积差异很大），三个样本：

| 世界 | 森林 | 草原/稀树草原 | 荒漠 | 高寒/冰雪 |
| --- | --- | --- | --- | --- |
| A（温带为主） | 47.6% | 31.2% | 8.9% | 12.3% |
| B（极地陆地多） | 42.1% | 14.1% | 3.3% | 34.8% |
| C（中纬大陆大） | 36.1% | 33.2% | 18.5% | 12.3% |

关键校正：冰盖条件收紧后，冰盖从占陆地 **30.5% 降到 5.9%**（此前整幅图
一半是白色，视觉上就是「荒漠」）；针叶林允许延伸到苔原带（真实泰加林
可到 70°N）；冷带的降水门槛必须比温带低得多（高纬年降水只有 200~400 mm，
按降水量是荒漠级，但潜在蒸散更低，实际是湿润泰加林 ——
沿用温带门槛会把整条亚寒带涂成「极地荒漠」）。

### 6. 这一轮的返工：从「看着假」到可判据

用户的反馈只有五个字：「气候很不自然啊。」这句话不能直接执行，于是先把
「不自然」拆成四个**能在图上指出来**的病象，再逐个定位到数值成因：

| 病象 | 量化后 | 真正的原因 |
| --- | --- | --- |
| 降水呈发丝状脉络、线间大片平涂 | 降水高频指数 0.197（温度只有 0.108） | `rise` 用**相邻两格原始高差**算地形雨，每道小沟都下雨；沉积又直接累加在本格，1 格宽的湿线被反复强化 |
| 群系碎成「迷彩服」 | 斑块中位数 **39 格**（等效半径 3.5 格） | 阈值切分沿等值线切碎 + 逐格高频噪声（`noise(scale=4)×0.18`）直接叠在降水上，幅度足以跨过 0.26/0.58 这些门槛 |
| 中纬度出现大片白色冰盖 | 50°S 的山上判成「极地冰盖」 | 判极性用的是**真实气温** `t`，而 `t` 已被 `rel×0.42` 的海拔降温污染过 |
| 南半球整体比北半球冷 | 同纬度陆地均温差 0.07~0.17 | ① 大陆度项写成单向降温 `t -= conti·(…)`，南半球陆地少就更冷；② 温度噪声是 (nx,ny) 的固定函数，逐行删均值之前，陆地落在噪声高值区就整体偏暖 |

#### 修法一：把「逐格」换成「场」

气候模块自带三个场算子：`boxBlur`（可分离盒式模糊，O(N)）、`mixBlur`
（按比例扩散一步）、`rowDemean`（逐行减均值）。

地形雨改用**模糊过的海拔**算抬升（气块尺度远大于一格）；每遍平流后做一次
35% 的 3×3 扩散；降水沉积场每遍也模糊一次；最后再做两级场模糊。
雨影、内陆梯度、迎风坡湿润这些**气候信号**全部保留，去掉的只是它们的
1 格宽轮廓 —— 降水高频指数 0.197 → **0.033**。

#### 修法二：纬度与海拔必须拆成两个变量

```
t     = 含海拔降温的真实气温（写回 cell.temp）
tSea  = t + rel × LAPSE   海平面等效温度（写回 cell.tempSea）
```

- 纬度气候带一律用 `tSea` 判 —— 它与海拔无关，南北对称，是纯粹的纬度代理；
- 垂直分带只用 `rel`，并且**雪线随纬度下降**：`snowline = 0.42 + 0.50 × tSea`
  （赤道约 0.92，极地约 0.42）。这样「热带的高山」和「两极的小丘」
  都能正确判成冰雪，而「温带的普通高原」不会再被涂白。

`tSea` 必须在 `clamp01` **之前**算：极区真实温度是负的，一旦截到 0，
`+rel×LAPSE` 就再也反推不回原值 —— 实测北极大陆会被算出 `tSea=0.35`，
整块极地长满泰加林。

#### 修法三：降水归一化用「两端分位锚定 + 反解 gamma」

物理模拟给的是**相对**干湿，绝对量级取决于一堆系数。试过两种归一化都不行：

1. `pow(v / P97, γ)`：模拟场方差太小（p50 只有 p95 的 0.66），γ=1.2 森林 55%、
   荒漠 7%（整图一片绿），γ=1.6 温带全变荒漠。刀尖上走。
2. 分位映射（按名次重排成固定分布）：份额可控，但**丢掉了绝对值** ——
   实测把副热带海面水汽从 0.58 压到 0.28，输出降水一个数没变，
   因为「沿海」在整幅图的干湿排序里位置没动。于是「副热带西岸该是沙漠」
   这类**量级**信息被洗掉，海岸又变回等宽的绿边。

最终方案：`P03 / P97` 映射到 0 / 1，再做幂次拉伸，**gamma 由中位数反解**
（要求中位数落到 `MED_TARGET`）。它是全局单调变换，只改标尺、不改任何
空间结构；同时因为锚点固定在分位上，份额可复现。

> **gamma 的夹取范围必须允许 < 1**。模拟场是右偏的（大部分陆地在中低湿度），
> 中位数落在区间偏左（实测 0.22），要拉到 0.40 需要 gamma ≈ 0.6。
> 早先夹在 `[1.1, 3.0]`，等于禁止提亮，gamma 被钉死在 1.1，
> 实际中位数只有 0.26 —— 而注释还写着「中位数已锁定」。

#### 修法四：群系去碎斑

`despeckleBiomes()`：3×3 邻域多数表决，2 遍。刻意保守 ——
只处理陆地格、只统计陆地邻居（否则海岸会被 5 个海洋邻居投票投成海）、
需要 ≥5/8 一致才改判。斑块中位数 39 → **105 格**，孤立碎点 0.10%。

`applyWaterInfluence()` 重新分类之后必须再去一次碎斑：河流是树枝状网络，
「沿河变湿」会在河网上切出一串细碎小块。

#### 修法五：草原不是沙

群系色经过 renderer 的「向亮度去饱和 26% + gamma 0.88 提亮」之后，
**卡其色草原会变成浅沙**。草原占陆地 1/3，于是整块大陆看起来像沙漠星球，
而分类表上写的是「森林 48% / 草原 31% / 荒漠 9%」。草原色必须给成
橄榄绿（约 120,130,70），和沙漠（约 190,175,145）在明度上真正拉开。

同时把 7 种森林从「同一段绿里改一点点 RGB」改成按色相分开：
寒温带偏青墨绿、温带偏黄亮绿、热带高饱和深绿、季风林黄绿。

`tools/verify-climate.js` —— 32 项判据，10 个 seed 全部通过：

### 7. 第二轮返工：从「能判据」到「像地球」

上一轮把 32 项判据全部跑绿了，但图上仍然有几处一眼假的。这一轮全部
先量化、再动手。按「改动影响面」从大到小：

#### 一、地形没有测高曲线（根因，改在 `map-generator.js`）

详见「海拔分层与雪山」一节。一句话：**陆地整体高了 5~6 倍**，
`rel` 中位数 0.264（≈2300 m）。雪地占陆地 22.6%、高寒群系 35.5%、
草原只剩 12.6%。改成按地球测高曲线做分位映射后，
`rel<0.023` 占 33.0%（地球 33%）、`<0.113` 占 82.0%（地球 82%），
雪地回到 1.6%，草原回到 26%。

这是这一轮最大的发现，也是前面几轮「气候不对」的真正根：

> 所有「雪线太低」「苔原太多」「温带森林被压成针叶林」的现象，
> 看起来都是 `classifyBiome` 的阈值问题，实际是**高度场的分布形状**
> 从来没人管过。阈值是在错误的标尺上反复调的。

#### 二、洋流在经向上完全均匀 → 副热带整圈是沙漠

判据给出的第一条硬证据：

```
+25~35° 东岸沿海降水 0.570    西岸沿海 0.565    差 −0.005
```

东西岸一模一样。整条副热带被涂成一圈沙色，亚热带常绿林占陆地 **0.06%**
（等于不存在）。

根因在 `oceanCurrents()`：

- 行星风场只依赖纬度，所以整行风的 u/v 完全相同；
- 第 3 步「西边界流加强」只对**每行最左一段海洋**生效，而且
  `dir = |lat|<30 ? hemi : -hemi` 的符号与注释相反（注释写暖流、算出来是寒流）；
- 再被 3 次拉普拉斯平滑抹平。

实测东西岸海格的平均流速**完全一致**（`(u,v)=(-0.25,0.00)` 对 `(-0.25,0.00)`），
沿海陆地的 `tempSea` 差只有 0.001~0.009。

新增 `coastalSst()`，只用海盆几何，不依赖那套不可靠的风生环流：

> 一个海格若**左侧**陆地更近 → 它在海盆西缘（贴大陆东岸）→ 暖流；
> 若**右侧**陆地更近 → 海盆东缘（贴大陆西岸）→ 寒流。

返回值 `warm ∈ [−1,1]`，离岸 `exp(−d/14)` 衰减、`5°~58°` 纬度窗。
它同时接到两个地方：

- **温度**：`t += sstField · 0.13`。`sstField` 对陆格取最近海岸海格的值再
  按 `exp(−d/14)` 衰减（BFS 顺带记录 `seaSrc`，即「最近的**海岸海格**是哪一个」）。
  0.13 ≈ 纬度上 12° 的温差 ≈ 8~10 °C，与黑潮/湾流相对加利福尼亚/加那利
  寒流的实际温差相当；
- **水汽**：`floor = (0.28 + 0.72·rowBase) · exp(0.85·warm)`。用指数是因为
  蒸发通量对海温超线性（Clausius-Clapeyron，每升 1 °C 饱和水汽压约增 7%）。

#### 三、副热带「无风」→ 水汽一步也上不了岸

改完海温之后东岸只比西岸湿了 0.135，还是不够。再查风场：

```
30° 处 tradeW = e^−(15/13)² = 0.264，westW = e^−(15/14)² = 0.317
u = −0.85×0.264 + 0.95×0.317 = 0.077
```

信风分量与西风分量在 30° **几乎抵消，风速 0.077**。而 30° 正是副热带
高压带（真实世界的「马纬度」，无风带）。没有风就没有平流：
22 遍 `ADV_STEP=8` 的推进 + 30% 的 3×3 扩散，半径只有约 2.5 格。
海面水汽再怎么按海温调，也只在海岸描出一条 2~3 格宽的绿边。

真实情况是副热带并非无风：夏季海陆热力差 + 海风环流会把海洋边界层
整层推上岸。所以不去硬改风速，而是让**近岸陆地空气向「该处海面的
平衡水汽值」靠拢**：

```js
const seaWarm = sstField[idx];
const supply = clamp01((0.28 + 0.72 * rowBase[y]) * Math.exp(SST_MOIST * seaWarm));
m = m * (1 - SST_COAST_MIX) + supply * SST_COAST_MIX;     // SST_COAST_MIX = 0.45
```

暖流岸 → 平衡值高 → 海岸湿润；寒流岸 → 平衡值低 → 海岸干燥
（撒哈拉/纳米布直抵海边）。衰减由 `sstField` 自身承担，
湿润带只有 40~60 格宽，进不到大陆腹地。

副作用是**碎斑**：海岸带会在群系阈值上切出细长的条，判据「群系连片」
从 154 格掉到 61 格。于是补了下一步。

#### 四、小碎块归并（`mergeSmallBiomeBlocks`）

3×3 多数表决只能吃掉 1~2 格的孤立点。阈值切分产生的碎块常常是
20~80 格的长条，八邻里大半仍属于自己 —— 表决不但吃不掉，反而会保护它们。

新增一个**整块**归并：4-连通标号 → 面积 < `N/6000`（50~85 格）的块 →
整块并给「邻接最多的外部陆地块」。只决定整块改成什么，不动块内部，
所以不会把大区域揉碎；被水围住的孤岛原样保留。

群系斑块中位数 61 → **333 格**，孤立碎点 0.00%。

#### 五、地形雨的阈值切换

```js
if (rise > 0.010) { orographic = min(0.55, rise*9.0); rain = m*orographic; m -= rain; }
else             { precipAcc += m*0.012; }
```

在 `rise = 0.010` 这一点上，降雨量从 `m·0.012` **跳到** `m·0.09`（7 倍），
同时 `m` 的扣减从 0 跳到 0.09。降水图上因此出现一块块**硬边的深蓝斑**。
改成连续形式 `orographic = 0.012 + max(0, rise)·9`（坡度为零时正好退化成
原来的对流雨），背风坡的 `if (rise < −0.010) m *= 0.975` 同样改连续。

#### 六、雪线不能用幂函数

上一版写 `snowline = 0.55 · tSea^1.3`，在赤道对（0.55 ≈ 4870 m）、
在高纬也对（65° 得 0.167 ≈ 1480 m），但**中低纬错得厉害**：
20° 算出 0.445（3940 m），而真实雪线在墨西哥/玻利维亚一带约 4800~5000 m。
真实雪线在 0~30° 几乎是平的（太阳高度角变化小），30° 之后才陡降 ——
幂函数做不出「先平后陡」。实测后果：`delta` 种子中低纬冰雪 4.44%。

改成按纬度逐点标定的分段表（见「海拔分层与雪山」），中间线性插值。

#### 七、河流绿洲带把整个世界泡湿了

气候阶段把降水中位数精确钉在 0.37（`MED_TARGET`），可地图生成完之后
实测中位数是 **0.487**。差额全部来自 `applyWaterInfluence()`：
半径 16 格、强度 0.40 的「沿河加湿」，而河流网络很密，
「距河 ≤16 格」已经覆盖了大部分陆地 —— 等价于给整个世界加了一档湿度。
森林 58.8%、荒漠只剩 9.6%，副热带的沙漠带被抹掉。

收到半径 9、强度 0.30：`d=1 → 0.71`、`d=5 → 0.31`、`d=9 → 0.10`。
既保留「沿河绿洲」，又不改全局水位。中位数 0.487 → 0.446。

> 这条是「**下游一步悄悄改掉上游辛苦标定的量**」的典型。
> 只要有两个阶段都动同一个字段，就必须有人在最后量一次。

#### 八、gamma 上限卡住了归一化

同一类问题：`gamma` 夹在 `[0.45, 3.2]`，而加入海岸加湿后模拟场从
右偏变成左偏（多数陆地靠海），反解需要 4.1 → 被夹在 3.2，
归一化**没达到自己写的目标**。放宽到 5.0。

#### 九、极地海冰（`renderer.js`）

没有海冰的两极就是一片纯蓝海水，一颗有完整三圈环流的行星却不结冰。

放在**渲染层**而不是群系分类里，理由有二：

- 群系里的 `深海/海洋/浅海` 只按深度判，`极地冰盖` 是给陆地冰帽的；
  一旦把海冰也做成群系，`despeckleBiomes` 与 `mergeSmallBiomeBlocks`
  会把它当成陆地邻居参与投票，沿海陆地的群系会被冰一路蚕食，
  「陆地构成」的统计也会被海面污染；
- 海冰是**海面的相态**，不是植被带。

判据用海温（`tempSea`）而不是纬度 —— 洋流会把冰界推歪（真实地球：
北大西洋 70°N 终年不冻，同纬度的白令海结冰）。按纬度画会得到一条
完美水平的白带，那是最容易露馅的假。再叠一层随经纬度缓慢变化的
正弦扰动，让冰缘犬牙交错。

#### 这一轮又改了三处判据

| 判据 | 原来的问题 | 改成 |
| --- | --- | --- |
| 分带群系（亚寒带/温带） | 写死北半球，`theta` 种子 35~55°N 只有 **112 格**陆地、60~70°N **0 格**，判据因「样本为空」报失败，输出却是「温带不是阔叶林 0%」 | 半球回退（哪个半球够 400 格用哪个）；两个半球都不够则**跳过**并打印格数 |
| 大陆度「越深入内陆越干」 | 用全样本 Pearson r。深内陆那 1~3% 的陆地往往是腹地高山，地形雨让它们比海岸还湿 → r 被拉向 0（`gamma` 种子 +0.029），但同一张图 0~5 格均值 0.656、20~45 格 0.446 | 改**分桶比**：近岸 0~5 格 ÷ 内陆 20~45 格 ≥ 1.15；r 只作参考打印 |
| 温带高寒 < 15% | 阈值是在「陆地高 5 倍」时定的 | 放宽到 25%（实测跨 seed 0.7~18.6%，超过的是真多山的 seed，不是系统性错误） |

## 地表材质纹理

只有几何起伏 + 光照时，地表是光滑渐变色，像塑料模型。
现在叠加**多尺度材质纹理**（`renderer.buildTextureMap()`）：

- 绿地：植被斑驳（成片树林与裸地交错）；
- 岩石区：碎石颗粒，对比更强；
- 雪区：细腻的风蚀纹理；
- 再加一层逐像素细微颗粒增加「质感」。

> **性能**：若在 `shade()` 里逐像素调用噪声，1600×800 需要约 1500 万次采样，
> 单次渲染 2.7 秒。改为**预计算纹理表 + 查表**后降到约 1.4 秒。

## 与真实遥感图的配色对比

以 NASA Blue Marble（1600×800）为参照做的色彩采样：

| 区域 | 真实遥感图 | 本项目 |
| --- | --- | --- |
| 深海 | (18,36,58) 近乎黑 | (46,104,152) 深海军蓝 |
| 浅海 | 偏青 | (132,208,214) 青绿 |
| 冰盖 | (235,236,237) | (228,236,244) |

真实遥感图的海洋接近黑色，但这是**地图**不是卫星照片——完全照搬会显得沉闷压抑。
因此取中间路线：深海保持明显的蓝色而非发黑，亮度约为遥感图的 3 倍。

## 真实遥感图采样标定

配色与纹理不是凭感觉调的，而是对 **NASA Blue Marble**（1600×800）做统计后标定。

### 实测亮度分位

| 分位 | 全图亮度 | 海洋亮度 | 陆地亮度 |
| --- | --- | --- | --- |
| p5 | 5 | 5 | 35 |
| p25 | 15 | 10 | 78 |
| p50 | 34 | **20** | **176** |
| p75 | 92 | 39 | 239 |
| p95 | 241 | 66 | 246 |

**关键发现：真实海洋与陆地的亮度比约为 1:9，对比极强。**

### 由此定位到「纹理跟没开一样」的真正原因

旧配色的地形色表全部落在 128~236 这个窄区间，海洋约 150、陆地约 180，
**两者亮度比只有 1:1.2，几乎糊成一片**。在这种压缩的动态范围里，
任何 ±10% 的材质纹理都会被淹没 —— 问题不在纹理强度，而在明度对比。

### 重建后的配色

- **陆地**：暗端压到 45（深绿森林）、亮端提到 243（沙漠/雪），
  按实测分位拉开动态范围，纹理才有立足之地；
- **海洋**：深海压到 (22,56,96)。遥感图实测是 (18,36,58) 近乎黑，
  但按「不要太黑」的要求取中间值——亮约 2.5 倍，既保留深度层次又不沉闷；
- **纹理强度**按真实地表的「空间不均匀性」分级：
  森林 0.30 > 岩石 0.42 > 雪 0.07（雪面最光滑）；
- 叠加逐像素颗粒（±5%），模拟真实地表的细碎明暗跳变。

### 实测效果

以 NASA Blue Marble（4096×2048，无云）为参照，按同一口径（蓝通道判别水陆）
做统计对比，逐轮校正后：

| 项目 | 真实地球 | 本实现（校正后） | 校正前 |
| --- | --- | --- | --- |
| 海洋平均 RGB | (16, 103, 156) | **(34, 99, 147)** | (56, 118, 150) |
| 陆地平均 RGB | (177, 185, 173) | **(164, 169, 143)** | (151, 156, 125) |

由此定位到两处偏差：

- **海洋红通道过高**（+40）：色带红分量偏大、蓝分量偏小，海水发灰发青，
  像浅潟湖而不是深海；按真实值压低红、抬高蓝，并压小大陆架提亮幅度
  （原先近岸 +10 会让大片浅海接近青绿）；
- **陆地偏暗偏黄**（蓝通道低 48）：群系色卡是按「设计色」而非真实反射率给的，
  饱和度过高；真实影像还受大气散射影响，整体被洗灰并提亮。
  因此在生成卫星底色时统一做一次「向亮度去饱和 34% + 提亮 17%」，
  近似模拟大气程辐射，而不是随手加滤镜。

> 剩余差距（陆地蓝通道仍低约 30）主要来自本项目仍保留「地图」而非
> 「照片」的取色倾向：植被绿比真实影像更饱和一些，以便在 2D 地图上辨认。

### 第二轮：消除「枯黄」观感

以真实影像的**色相分布**为判据，又定位到三处：

| 指标 | 真实遥感影像 | 本实现（第一轮后） | 本实现（现在） |
| --- | --- | --- | --- |
| 陆地饱和度 | 0.061 | 0.27 | 0.22 |
| 陆地明度 | 0.66 | 0.41 | — |
| 黄色段色相占比（60~90°） | 14% | 36.4% | **9.4%** |

1. **调色板偏黄**：草原/稀树草原色卡的红分量过高，落在黄色段。
   把草甸类改成偏黄绿（降红、提蓝），裸岩色去掉暖调（128/122/112 → 132/130/124）；
2. **绿色太深**：泰加林原为 (46,82,56)，比真实影像的植被暗得多，整体提亮约 20%；
3. **纹理过强**：材质表的植被斑驳幅度是 ±30%，在明度更高的卫星视图里显得
   「斑驳发干」。压到 65%，逐像素颗粒由 ±5% 降到 ±4%。

最后加一条 **gamma 0.88 的提亮曲线**（抬中间调、几乎不动高光），
避免沙漠/雪线被线性乘法吹爆成纯白。

## 手绘古地图（handdrawn 视图）

不是给卫星图叠滤镜，而是一套**独立的着色语言**，模仿 17~19 世纪铜版地图：

| 元素 | 做法 |
| --- | --- |
| 底纸 | 羊皮纸色 + 每像素纤维颗粒 |
| 陆地 | 按海拔决定墨色浓淡（越高越深） |
| 山体 | **固定角度的铜版排线**，线距与墨度随坡度增加 |
| 等高线 | 每 1/16 相对高度描一条细墨线 |
| 海岸 | 紧邻海洋的陆地格压深，形成勾边 |
| 水体 | 淡青灰平涂 + 低频水纹 |
| 河流 | 由蓝色改为深褐墨线，线宽收细 |
| 湖泊 | 淡水面 + 墨线岸 |

### 踩过的坑：排线会变成噪点

第一版按「与等高线平行」生成排线 —— 逐像素求出的坡向在相邻像素间会抖动，
用它做条纹坐标会把排线打成随机噪点，看起来像**脏纸**而不是刻线。
铜版画实际用的是**固定角度**排线，靠线距/线宽表现坡度。改成固定 25° 后，
线条干净且密度随坡度变化。

### 与 3D 的关系

3D 球体的贴图来自「当前显示模式」，所以切到手绘模式再进 3D，
得到的是一颗**手绘地球仪** —— 纸色海陆、排线山体、墨线海岸都直接贴到球面上，
再叠上真实的顶点起伏与云层。无需任何额外分支。

## 3D 视图（globe.js）

旧实现只是给一个光滑球体贴上 2D 地图纹理，没有任何几何起伏，
也没有云层——本质上是「贴了图的地球仪」。现在重建为三层结构：

### 1. 地表：真实顶点位移

不再用光滑球面，而是遍历 `SphereGeometry(1, 256, 128)` 的 33153 个顶点：

1. 把顶点球面坐标反推为经纬度；
2. 双线性采样 2D 地图的海拔；
3. 陆地向球外隆起（沿法线位移），海洋保持球面；
4. `computeVertexNormals()` 重算法线，山体产生真实明暗与阴影。

位移幅度 `DISPLACEMENT = 0.055`（球半径的 5.5%）。
真实地球珠峰只有半径的 0.14%，照搬几乎看不出起伏，
这里刻意夸张约 40 倍，属于「合理夸张」。

配合由海拔梯度生成的**法线贴图**，粗网格上也能看到细碎的表面凹凸。

### 2. 体积云

程序化生成 1024×512 云图，贴在稍高于地表的球面上：

- 云量按**真实大气环流**分布：赤道低压带多对流云、副热带高压带晴朗、
  中纬西风带气旋活跃、极地少云；
- 三层噪声叠加出絮状云团结构，而非均匀灰雾；
- 云层独立缓慢自转（`cloudSpin`），与地表产生相对运动 → 立体感；
- 可用「显示云层」开关关闭。

### 3. 大气辉光

球体外侧用 Fresnel 边缘光着色器（`BackSide` + `AdditiveBlending`），
模拟大气散射产生的蓝色薄边。

### 壳层半径必须包住山峰

位移幅度上限是 `1 + DISPLACEMENT = 1.055`，因此：

| 壳层 | 旧值 | 现在 | 后果（旧值） |
| --- | --- | --- | --- |
| 云层 | 1.018 | **1.075** | 相对高度 > 0.47 的山脉直接戳出云壳，云被山体切开 |
| 大气 | 1.045 | **1.10** | 山峰顶穿辉光壳，球体边缘出现断掉的亮环 |

这类问题在正视图看不出来，只有转到**球体剪影边缘**才会暴露。

### 颜色与 2D 不一致（sRGB 双重编码）

贴到球上后整张球发白发灰，实测平均提亮 **+57**、最坏 +133。

根因是色彩空间只做了一半：`renderer.outputEncoding = sRGBEncoding`（输出端做了
线性 → sRGB 编码），但**贴图端没标 sRGB**，被当成线性数据采样，于是等于做了
一次双重 gamma。而代码里写的 `if (THREE.SRGBColorSpace) tex.colorSpace = ...`
在本地 three.js **r128** 上根本不存在（r128 用 `texture.encoding`），分支永不执行。

现在用 `markSRGBTexture()` 同时兼容两种 API，只对**颜色**贴图设置；
粗糙度/法线属于线性数据，保持不动。修复后逐点比对「渲染色 vs 贴图色」，
平均差 **0.04**、中位 **1.6**（0~255 量级），已还原到与 2D 一致。

### 极点纹理变形（极冠收敛）

等距圆柱的极点是「一整行像素收拢成一个点」，带来两个固有缺陷：

1. 极点行的横向色差被投射成**放射状辐条**（西瓜纹）；
2. 该处 UV 各向异性趋于无穷，GPU 只能选最粗的 mip，极点糊成一坨色斑。

真实行星极区本来就是均质冰盖，因此在生成 3D 专用贴图时，把极点向外 12°
的行逐行向「极冠平均色」平滑混合（`#prepareGlobeCanvas`）：

- 逐行与原始等距圆柱渲染对比：**赤道带最大差 0**（完全不受影响）；
- 极冠内亮度标准差从 23 降到 **1.3**（平均 0.3），辐条消失；
- 南极大陆海岸线在 ~70°，不在收敛范围内，轮廓保持锐利。

> **踩过的坑**：`poleDist` 是「到极点的角距离」（极点 0、赤道 90），
> 第一版误写成「小于 78 就跳过 + 权重 `(poleDist-78)/12`」，方向正好相反 ——
> 结果把**赤道带**混成了极冠白色，球上出现一圈刺眼的**赤道白圈**。
> 回归脚本现在会逐行比对 3D 贴图与原始渲染，赤道带必须零改动才能通过。

### 朝向对齐

贴图 x 方向做了镜像（`repeat.x = -1`）以匹配 three.js 球体 UV，
球体再绕 Y 轴转 `-90°`，使**地图 x = W/2（经度 0°）正对相机**。
之前用的是 +180°，进入 3D 后正面朝向地图 1/4 处，会让人觉得
「左右没对齐、和 2D 中间对不上」。

云层使用同一基准角 `cloudBaseAngle`，只是在其上叠加自转，
否则云会相对陆地整体偏转 90°。

### 云图的「左右接不上」与极地云被压成细条

云图噪声原先把经度压成 `corrU = (nx-0.5)*cos(lat)+0.5`，
本意是「补偿高纬经线收拢」。但 `noiseSeamless` 内部**已经是**把
`(nx, ny)` 映射到球面单位向量再取 3D 噪声，特征本来就是物理各向同性的；
再压一次等于把高纬云团沿经度挤扁 —— 球面上看就是绕极点的**径向细条**。
更直接的问题是：这个映射把 `[0,1]` 压成了一段**子区间**，
`nx=0` 与 `nx=1` 采样到不同位置，于是云图左右边缘对不上（接缝）。

改回直接把 `nx` 交给 `noiseSeamless`：接缝天然连续，特征天然各向同性。
判据是「高纬横向梯度 / 纵向梯度 ≈ cos(lat)」（球面噪声的必然结果）：

| 纬度 | 云图 比值 / 理论 cos(lat) |
| --- | --- |
| -68.4° | 0.59 / 0.37 |
| -46.8° | 0.82 / 0.69 |
| -21.6° | 0.94 / 0.93 |

俯视极点的梯度各向异性（径向能量 / 切向能量）测下来
北 **1.25**、南 **0.80**、赤道参照 **1.30** —— 极区已与赤道同级，
不再有绕极点的细条。云图接缝处的列差（均值 12.1）也与相邻列差（11.1）同级。

### 光照调优

目标是让 3D 里的海色接近 2D 的深蓝 (22,56,96)，而不是被环境光提亮成灰白：

| 参数 | 问题值 | 修正值 | 说明 |
| --- | --- | --- | --- |
| metalness | 0.05 | **0** | 地球不是金属，非零会产生镜面白斑 |
| 海洋粗糙度 | 60 | **150** | 60 太光滑，强光下高光爆白 |
| sun 强度 | 2.1 | 1.85 | 主光决定明暗 |
| ambient 强度 | 0.75 | **0.34** | 环境光无差别加亮，深海被抬得最明显 |

### 依赖本地化

原先 three.js 走 CDN，实测该 CDN 在本机**连接超时**，
意味着 3D 视图此前一直是坏的（报 `THREE is not defined`）。
现已下载到 `js/vendor/`，3D 可离线使用。

## 性能

一处关键认知：这张图的开销不在「算法复杂度」，而在**同一次噪声被反复算了很多遍**。
优化前生成阶段约 1700 万次 `noise3D` 采样，渲染阶段每帧还要再算 261 万次，
而这两处算出来的值绝大多数是重复的。因此优化的主线是「**算一次、存下来、查表**」，
而不是换算法。所有结果与旧实现在数学上等价（固定种子出图逐位一致）。

### 分项实测

环境：Node 22（1600×800，固定种子 `bench-fixed`，`tools/bench.js`，
3 次运行取平均；浏览器数字与此同量级）。

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 生成阶段噪声采样 | 1700 万次 | **384 万次** |
| 生成总耗时 | 14.9 s | **10.5 s**（并行开启后更快，见下） |
| 渲染每帧噪声采样 | 261 万次 | **0** |
| 等距投影地形着色 | 500 ms | **324 ms** |
| 罗宾逊投影地形着色 | 1943 ms | **328 ms** |
| 完整重绘（地形层+矢量层+合成） | 1652 ms | **287 ms** |
| 仅切叠加层（经纬网/季风/洋流） | ~1650 ms | **36 ms** |
| 编辑后重建（`updateOceanDepth`） | 1183 ms | **287 ms** |

生成阶段现在的构成：地形 3.64 s / 气候 1.30 s / 水文 0.69 s / 海深与纹理 1.73 s。

### 地形并行（`terrain.js` + `terrain-worker.js`）

地形逐像素独立，天然可按行带切分。`js/terrain.js` 是主线程与 Worker 共用的计算内核，
`js/terrain-worker.js` 只负责 `importScripts` + 构造噪声 + 回传 `ArrayBuffer`（transferable，零拷贝）。

- 线程数取 `navigator.hardwareConcurrency`，上限 8。
- **必须显式播种**：每个 Worker 各自 `new SimplexNoise(seed)`，
  否则各线程置换表不同、行带交界处会出现台阶。已用 `tools/verify-parallel.js` 逐位验证：

  ```json
  { "threads": 4, "singleThreadMs": 3647, "parallelMs": 1288, "speedup": 2.83,
    "identical": true, "diffCount": 0,
    "seamSteps": [{"row":200,"step":0.00175},{"row":400,"step":0.0018},{"row":600,"step":0.00212}],
    "interiorRowStepAvg": 0.00211 }
  ```

  交界行间差与内部行间差同量级，说明看不到接缝。
- `file://` 协议下创建 Worker 会被同源策略拦截，此时自动回退到主线程分块计算
  （64 行一块、块间 `setTimeout` 让出），进度条与结果完全一致，只是慢一些。
  状态栏会显示「地形 N 线程并行」或省略该项，可作为是否真正并行的肉眼判据。

### 渲染侧的四层缓存

1. **albedo 缓存**：等距投影下着色时顺手把 RGBA 写进 `Uint8ClampedArray`；
   切到罗宾逊/等角投影时直接对 albedo 做 4 邻双线性重采样，
   替掉原先「每个画布像素重新 `shade()` 一次」（投影下还要 shade 4 次）的写法。
2. **噪声层缓存**：`macro` / `meso` / `micro` / `ice` 四层噪声只依赖像素坐标，
   初始化时一次算完存成数组，之后 `shade()` 直接取值。
3. **画布分层**：`terrainCanvas`（仅地形）→ `textureCanvas`（地形+河网+经纬网）→
   主画布（+季风/洋流）。只有 `terrainDirty` 时才重画第一层。
4. **查表**：`Math.pow` 换成 2048 级 gamma 表 + 线性插值；
   盒式模糊去掉内层的 `% W` 取模，只对首尾列特判环绕。

## 已知限制

- 生成一张 1600×800 地图约需 15.4 秒（单线程口径，进度条可见）：
  地形 4.13 s、气候 2.00 s、水文 0.87 s、海深与纹理 1.74 s。
  地形是唯一能并行的阶段，4 线程实测 1.29 s（2.83×），整体约降到 12 秒；
  其余（气候、水文、海深与纹理）是串行算法，暂未并行化。
  瓶颈是 `noise3D` 本身（约 26 ns/次 × 384 万次），
  继续提速需要换噪声实现或降采样，属于另一条路。
- 2D 全量重绘（地形层+纹理+矢量）约 0.29 s，仅切叠加层约 36 ms；
  切视图/投影首次会重建纹理，仍有短暂可感知延迟。
- 地形并行依赖 Web Worker，`file://` 直接打开会回退单线程。
- 配置导出为 base64 JSON（1600×800 约 8 MB），体积较大。
- 极地冰盖区域不绘制河流与湖泊。

## 开发说明

- 源码无构建步骤：所有模块都是普通 `<script>` 加载的 IIFE，挂到 `window.FM` 命名空间。
  `build.js` 只是把这一堆文件内联成单文件，不参与开发流程。
- `js/terrain-ops.js` 是编辑器的纯算子层，**不要在里面引用 DOM 或 `window`**
  —— 它要能在 Node 里直接跑，这是编辑器能被量化验证的前提。
- 调整水文参数：`hydrology.js` 顶部的 `FILL_EPS`、`riverThreshold`（默认按
  地图格数比例）、`minLakeArea`；河流分级的宽度与颜色在 `renderer.js` 的
  `RIVER_LEVELS`。
- 调整编辑手感：`terrain-ops.js` 底部的 `EROSION_DEFAULTS`（编辑器与离屏预览
  共用同一份，改一处两边都变）与 `amplitudeFor()` 的幅度系数。
- 调试钩子：`window.__FM_APP__` 暴露了 generator / renderer / editor / globe，
  方便在控制台或自动化测试里直接操作。

### 离屏基准与校验（`tools/`）

改性能、调手感最怕「感觉变了」。这些脚本用 Node 直接加载业务代码，
不依赖浏览器，可反复跑出可比较的数字：

```bash
node tools/bench.js                # 生成 + 渲染分项耗时（假 canvas，固定种子）
node tools/verify-parallel.js      # 并行地形与单线程逐位比对
node tools/preview-region.js       # 选区塑形渲成图（原始 / 大陆 / 海洋，含 2 倍放大）
node tools/verify-region.js        # 20 项选区塑形自然度
node tools/verify-editor.js        # 12 项笔刷算子（当前未接线）
node tools/verify-integration.js   # 27 项编辑器接线
node tools/verify-build.js         # 10 项构建产物检查（需先 node build.js）
node tools/verify-climate.js [seed] # 32 项气候自然度判据（换 seed 反复跑）
node tools/preview-climate.js      # 温度/降水/群系/成品渲染四张图 + 纬度带构成
```

`verify-climate.js` 建议至少跑这 9 个 seed：
`climate-verify`、`alpha`、`beta`、`gamma`、`delta`、`epsilon`、`zeta`、`eta`、`theta`。
它们覆盖了「一整块北极大陆」「温带有巨型高原」「低纬几乎没有陆地」等极端地形 ——
单跑默认种子会漏掉这些。

其中 3 个 seed 会打印 `⏭ 样本不足，本 seed 跳过`（例如 `theta` 在
60~70° 两个半球合计 0 格陆地）。这是**跳过而不是通过**，会一并打印格数，
看到 0 格就应该明白这是抽样问题而不是气候问题。

`bench.js` 用 `vm.runInThisContext` + 手写 `installGlobals()` 加载脚本，
**不要换成 `vm.createContext` 沙箱** —— 跨上下文全局访问惩罚会让生成耗时虚高约 7 倍
（107 s vs 14.9 s），得到的数字毫无意义。

`verify-integration.js` 用 DOM 桩（canvas / overlay / renderer / generator）
驱动真实的 pointer 事件。踩过的两个坑：`pointerup` 监听在 `window` 上而不是
canvas 上（发给 canvas 会导致笔画永远不结束）；`getContext` 等桩方法缺一个就会
在链路深处炸出难懂的报错。

`verify-parallel.js` 里 `terrain-worker.js` 有一段 CJS 兜底：
`worker_threads` 环境下 simplex-noise 的 UMD 会挂到 `exports` 而不是全局，
所以 worker 里补了 `self.SimplexNoise = exports.SimplexNoise`。浏览器端不受影响。

`tools/smoke.js` 是 puppeteer 端到端冒烟脚本，逻辑完整但在无图形环境里
无法启动浏览器进程，可留作有桌面会话时的手动验证工具。
